# APU 프로젝트 학습

Python과 pandas를 기본적으로 사용해 본 학습자를 위한 APU 공기압축기 이상 탐지 학습 자료다. 3일 동안 하루 5시간씩 개념과 분석 이유를 익히고 실제 코드와 결과를 읽으며 발표 질문을 준비한다. 혼자 또는 두 명이 함께 배울 수 있다.

## 파일 구성

| 파일 | 용도 |
| --- | --- |
| [README.md](README.md) | 프로젝트 설정, 시작 문장, 명령 사용법 |
| [Project_Instructions.md](Project_Instructions.md) | 프로젝트 지침에 붙여 넣을 튜터 운영 규칙 |
| [학습자료.md](학습자료.md) | 15단원 수업, 코드 지도, 질문·평가, 일일 확인서, 저장 양식 |

분석 코드와 원자료는 이 저장소에 포함하지 않는다. 학습에 사용하는 실제 프로젝트는 [APU_data_analysis](https://github.com/anapo100/APU_data_analysis)다. 학습자료에 나오는 `src/`, `notebooks/`, `data/`, `report/`와 프로젝트 설명용 `README.md`는 모두 그 분석 저장소의 경로다.

## 프로젝트 설정

1. 새 ChatGPT 프로젝트를 만든다.
2. [Project_Instructions.md](Project_Instructions.md)를 열고 본문 전체를 프로젝트 지침 입력란에 붙여 넣는다. 파일만 올리면 지침 입력란은 채워지지 않는다.
3. [학습자료.md](학습자료.md)를 프로젝트 파일 또는 학습 소스로 올린다. 이 파일로 수업과 평가를 진행하고 확인서·저장 양식을 사용한다. 설정 방법은 이 README에서 확인한다.
4. 첫 대화에 분석 저장소 주소 `https://github.com/anapo100/APU_data_analysis`를 함께 전달해 어떤 자료를 읽을 수 있는지 확인한다. 웹 접근이 안 되면 해당 수업에 필요한 노트북과 `src` 파일을 별도로 올린다.

개념과 작은 예제는 원자료 없이도 배울 수 있다. 전체 분석을 실행하려면 분석 저장소의 [실행 안내](https://github.com/anapo100/APU_data_analysis#readme)를 따라 환경을 준비하고 `data/MetroPT3(AirCompressor).csv`와 `data/apu_failure_events.csv`를 별도로 준비한다. 고장 기록 CSV는 팀에서 정리한 자료다.

## 첫 대화

아래 문장을 입력한다. 처음에는 수업에서 부를 이름이나 원하는 별명을 알려 준다. 이미 이름을 말했으면 다시 묻지 않는다. 실명·학번·연락처는 필요 없다. 튜터는 편한 해요체로 설명하고, 한 번에 한 수업과 질문 하나씩 진행한다.

```text
나는 Python과 pandas를 기본적으로 사용해 봤어. 3일 동안 하루 5시간씩 APU 프로젝트를 배울 거야. 기초 개념과 분석 이유를 먼저 설명하고 실제 코드와 발표 질문을 연결해줘.

학습자료.md를 읽고 접근 가능한 자료를 확인한 뒤 첫 단원부터 시작해. 한 번에 한 수업과 한 질문씩 진행해. 편한 해요체로 설명하되 기초와 코드 풀이를 생략하지 말고, 내가 한 답과 실제 근거를 짚어 피드백해줘.
```

두 명이 함께 배우면 이어서 `2인 설정`을 입력하고 각자 사용할 이름을 알려 준다. 이름이 같으면 서로 구분할 별명을 정한다. 기존 기록에 이름이 없으면 누구의 기록인지 한 번 확인해 연결한다. 이미 연결한 기록은 다시 묻지 않는다.

질문 대상, 점수, 진도와 확인서에는 입력한 이름을 사용한다. 예를 들어 지민과 도윤으로 등록했다면 `지민: 답변`, `도윤: 답변`으로 제출한다. 이 문서의 이름은 사용법을 보여 주는 예시이며 실제 학습자 이름으로 미리 등록하지 않는다.

## 3일 학습 흐름

| 일차 | 배울 내용 | 연결되는 코드·자료 |
| --- | --- | --- |
| 1일차 | 평가 단위, 데이터 품질, 완전 주기, A16 특징, 고장 라벨과 시간 분할 | 노트북 01·02, 전처리·특징·라벨 모듈 |
| 2일차 | 시계열, 표준화와 Z-score, Isolation Forest, LOF, 검증을 통한 임곗값 선택 | 노트북 03·04, 시계열·모델·평가 모듈 |
| 3일차 | 혼동행렬, 경보 간격과 선행시간, 오탐·미탐 해석, 대시보드, 모의 심사 | 노트북 05, 경보·사례 분석 모듈, HTML 발표 |

하루에 50분 수업 5개를 진행한다. 각 수업 뒤에는 10분씩 쉬며 기록한다. 총 15단원, 수업 750분과 휴식·기록 150분을 합쳐 900분이다. 일일 점검은 매일 마지막 수업에서 끝나기 15분 전에 시작한다. 끝내지 못한 항목은 미완료로 남기고 다음 수업의 복습 시간에 이어간다.

## 자주 쓰는 명령

| 입력 | 하는 일 |
| --- | --- |
| `시작` / `계속` | 첫 수업을 시작하거나 현재 위치에서 이어간다. |
| `쉽게` / `복습` / `지도` | 설명 난이도를 낮추거나 복습하고, 학습 경로와 현재 위치를 확인한다. |
| `.ff 임곗값` | 해당 주제를 기초부터 자세히 설명한다. |
| `코드 src/evaluation.py curve_for_scores` | 접근 가능한 실제 함수를 읽고 입력·조건·출력을 따라간다. |
| `질문` / `힌트` | 연습 문제 한 개를 받거나 현재 문제의 힌트를 한 단계 받는다. |
| `심사` / `진단` | 발표 질문을 연습하거나 요청한 범위의 이해도를 확인한다. |
| `대시보드` | 실제 과거 데이터의 그래프·경보를 코드와 연결해 읽는다. |
| `저장` / `복원만` | 현재 상태를 JSON으로 받거나 보관한 상태를 복원한다. |

자료를 읽지 못했다면 개념 설명을 실제 구현 확인으로 받아들이지 않는다. 문제를 풀기보다 설명을 듣고 싶을 때는 그렇게 요청한다. 짧은 답이 어느 항목을 뜻하는지 애매하면 튜터가 한 번 확인한 뒤 평가한다. 확인 전에는 오답으로 처리하지 않는다.

## 두 명이 함께 배울 때

둘 모두 같은 15단원을 배우고 각자 15시간을 계획한다. 코드와 발표를 반씩 나누지 않고 수업마다 코드 설명·조작 역할과 질문·검토 역할을 바꾼다.

- 각자 먼저 별도 메모에 답을 적고 등록한 `이름: 답변`으로 제출한다. 혼자 학습할 때는 대상이 분명하면 이름을 생략해도 된다. 누구의 답인지 애매하면 채점 전에 한 번 확인한다.
- 튜터는 두 사람의 최초 답을 받은 뒤 정답·점수·모범답안을 공개한다. 상대 답을 먼저 봤거나 도움을 받았으면 그 사실을 기록한다.
- 최초 답과 수정 답, 받은 힌트는 사람별로 남긴다. 다른 활동 뒤에 푸는 변형 문제와 진도·점수도 따로 기록한다. 한 사람의 답이나 공동 결과물이 다른 사람의 학습 증거를 대신하지 않는다.
- `개인 전환 [이름]`은 현재 답변·질문 대상만 바꾼다. 예: `개인 전환 도윤`.
- `개인 모드 [이름]`은 선택한 사람의 개인 수업으로 이어간다. 예: `개인 모드 도윤`. 그 사람의 이름·점수·진도를 유지하고 다른 사람의 기록과 공동 산출물도 보존한다.
- `이름 변경 [현재 이름] → [새 이름]`으로 표시 이름을 바꾼다. 예: `이름 변경 도윤 → 바다`. 기존 기록은 그대로 이어지며 다른 사람과 합쳐지지 않는다. 같은 이름이 이미 있으면 구분할 별명을 다시 정한다.

## 하루 점검과 확인서

하루가 끝날 때 `일일 점검 1일차`를 입력한다. 두 명이면 `2인 점검 1일차`를 사용할 수 있다. 2인 모드의 `일일 점검`도 각자를 따로 확인한다. 다음 날에는 일차를 `2일차`, `3일차`로 바꾼다.

점검에서는 개념 설명(C), 코드 추적(P), 설계·한계 답변(Q)의 기록을 살펴본다. 부족한 과제부터 한 개씩 진행한다. 최초 답과 수정 답을 구분하고, 다른 활동을 사이에 둔 미공개 변형 문제로 다시 확인한다. 코드 손 추적과 실제 실행도 구별해 기록한다.

`일일 확인서 1일차`는 이미 남긴 기록을 확인서로 출력한다. 새 평가를 시작하거나 점수·진도를 갱신하지 않는다. 기록이 없으면 빈칸과 미확인으로 남긴다. 혼자 학습하면 현재 선택한 사람의 이름과 기록으로 개인 확인서를 출력한다. 두 명이면 각자의 이름으로 개인란과 공동란을 작성한다. 개인 모드로 바꿔도 다른 사람의 기록을 가져오거나 이름을 바꾸지 않는다.

검토자에게는 해당 일차 확인서와 실제 대화 발췌를 함께 전달한다. 코드를 실행했다고 기록했다면 셀 입력·출력도 함께 보관한다. [학습자료.md](학습자료.md) 제16~18절에 일차별 양식, 제19절에 검토자 안내가 있다. 사람 검토자의 승인·서명란은 실제 검토 전까지 비워 둔다.

## 저장하고 이어가기

1. `저장`을 입력하고 출력된 JSON을 직접 보관한다. 저장할 때는 다음 단원으로 넘어가지 않고 미답 문제도 그대로 둔다.
2. 같은 프로젝트의 새 대화에 보관한 JSON을 넣고 `복원만`을 입력한다. 다른 프로젝트로 옮겼다면 프로젝트 지침과 학습자료도 먼저 설정한다.
3. 표시 이름, 현재 단원과 미답 문제를 확인한다. 2인 모드라면 현재 대상과 두 사람의 기록도 확인한다. 예전 이름으로 저장했더라도 같은 사람의 기록으로 이어가며, 이전 기록에 이름이 없으면 먼저 소유자를 확인한다.
4. 맞게 복원됐으면 `계속`을 입력한다.

이름은 화면에 표시하는 용도이며 기록을 구분하는 내부 식별자는 바뀌지 않는다. 예전 A/B 저장 기록도 각각 연결해 복원하므로 다시 시작할 필요는 없다. 이름이나 소유자를 확인할 수 없으면 원본을 남겨 두고 한 번 확인한다. 사용자에게 A/B 입력을 요구하지 않는다.

기존 기록이 있으면 학습자료 제20절의 빈 상태 양식으로 덮어쓰지 않는다. JSON 외에도 대화 발췌와 증거 파일을 직접 보관한다. 자동 저장이나 대화 사이의 영구 기억을 전제로 하지 않는다.

## 자료를 읽을 때 확인할 점

학습자료의 기준 커밋은 `0fe88d151be114db2df8d63fcd06ca35ee572107`이다. 코드 설명과 수치는 해당 버전의 문서·코드·저장 출력에 근거하며, 원자료 전체를 다시 실행한 결과는 아니다. 코드가 바뀌면 읽은 커밋과 파일을 기록하고 해당 내용을 다시 확인한다. 상세 출처는 학습자료 제15절에 있다.

분석 저장소의 `README.md` → `data/README.md` → `data/COLUMN.md` 순서로 개요와 데이터를 읽는다. `report/presentation/index.html`은 18장 발표이며, 화면으로 보려면 같은 폴더의 스크립트·스타일·이미지·폰트도 함께 받아야 한다. 발표의 A16/B16/T2 확장 비교와 현재 `src`의 A16 주 분석은 구분한다.

대시보드는 실제 과거 데이터 탐색과 경보 재생용이다. 현재 설비의 실시간 상태나 실제 경보 발송을 보여 주는 것으로 해석하지 않는다. 수업에서 화면을 설명할 때는 직접 열어 본 부분만 근거로 삼는다.

일일 확인서는 대화에서 관찰한 학습 수행의 기록이다. AI 평가가 출석·신원·실제 공부시간이나 사람의 승인을 인증하지는 않는다. 3일 일정은 학습 계획이며, 이해가 부족한 단원은 남겨 두고 이어서 공부한다.
